### Проблемные зоны с учетом требований безопасности
#### Процесс 1.1. Учет пациентов
- Конфиденциальные (персональные и медицинские) данные пациентов хранятся без шифрования на общем диске
- Передача конфиденциальных данных по сети через незащищенные (без шифрования) каналы
- Ввод и обработка данных осуществляется вручную, что увеличивает вероятность ошибок и нарушения целостности данных
- В Excel-файлах и файлах других форматов хранятся конфиденциальные данные пациентов совместно с прочей информацией
- Отсутствует контроль и разграничение прав доступа к данным пациентов
- Отсутствует аудит доступа к конфиденциальным данным
#### Процесс 1.2. Ведение журналов записи пациентов
- Передача конфиденциальных данных по сети через незащищенные (без шифрования) каналы
- Ввод и обработка данных осуществляется вручную, что увеличивает вероятность ошибок и нарушения целостности данных
- Отсутствует контроль и разграничение прав доступа к данным пациентов
- Отсутствует аудит доступа к конфиденциальным данным
#### Процесс 1.3. Приём и учет платежей и бухгалтерия
- Финансовые (платёжные) и конфиденциальные (персональные - пациентов и сотрудников) данные хранятся на общем диске (в Excel-файлах и файлах данных 1C) без шифрования
- Передача конфиденциальных данных по сети через незащищенные (без шифрования) каналы
- Отсутствует контроль и разграничение прав доступа к данным
- Отсутствует аудит доступа к финансовым данным
#### Процесс 1.4. Приём пациента у мед. специалиста
- Персональные и медицинские данные пациентов хранятся на общем диске без шифрования
- Передача конфиденциальных данных по сети через незащищенные (без шифрования) каналы
- Ввод и обработка данных осуществляется вручную, что увеличивает вероятность ошибок и нарушения целостности данных
- Отсутствует контроль и разграничение прав доступа к данным
- Отсутствует аудит доступа к конфиденциальным данным
#### Процесс 1.5. Учёт анализов
- Конфиденциальные (персональные и медицинские) данные пациентов передаются через незащищенные (без шифрования) каналы
- Конфиденциальные данные передаются и хранятся без шифрования
- Обработка данных осуществляется вручную, что увеличивает вероятность ошибок, нарушения целостности и компрометации данных
- Отсутствует контроль и разграничение прав доступа к данным
- Отсутствует аудит доступа к конфиденциальным данным.
#### Процесс 1.6. Учет ТМЦ
- Финансовые данные хранятся на общем диске (в файлах данных 1C) без шифрования.
- Передача финансовых данных по сети выполняется через незащищенные (без шифрования) каналы
- Отсутствует контроль и разграничение прав доступа к данным
- Отсутствует аудит доступа к финансовым данным
#### Общие проблемы
- Отсутствие классификации и совместное хранение чувствительных (персональных, медицинских, финансовых) и прочих данных
- Отсутствие шифрования при хранении и передаче чувствительных данных
- Отсутствие контроля и разграничения прав доступа к данным
- Отсутствие аудита доступа к чувтствительным данным для чтения и изменения
- Передача чувствительных данных по незащищённым каналам (из лаборатории)
- Ввод и обработка данных для ведения учёта в файлах осуществляется вручную, что увеличивает вероятность ошибок, нарушения целостности или полного удаления данных
- Все системы и сервисы размещены на одном физическом сервере без резервирования, что значительно повышает риск уничтожения данных компании и остановку её деятельности
- Местами излишнее дублирование конфиденциальной информации
### Предложения по улучшению
#### Cписок данных и способы их защиты
1. **Перс. данные (PHI)**
    - Ф.И.О.
    - Дата рождения
    - Телефон
    - Электронная почта
    - Адрес прописки
    - Место работы или учёбы

    **Способы защиты:** шифрование для хранения и передачи, обфускация (токенизация), маскировка (динамическая при отображении в интерфейсах и детерминированная при отправке в озеро данных), контроль доступа (RBAC/ABAC), аудит доступа, автоматизация ввода и обработки, резервное копирование.
2. **Медицинские данные (PHI)**
    - Хронические заболевания
    - Результаты анализов (Клинические данные)
    - Результаты консультаций мед. специалистов
    - Диагнозы мед. специалистов

    **Способы защиты:** шифрование для хранения и передачи, обфускация (токенизация), маскировка результатов консультаций (динамическая при отображении в интерфейсах для всех кроме мед. специалистов и статическая при отправке в озеро данных), контроль доступа (RBAC/ABAC), аудит доступа, автоматизация ввода и обработки, резервное копирование.
3. **Финансовые данные пациентов**
    - История операций пациентов
    - Реквизиты платежных инструнтов пациентов (номера карт - PCI DSS)

    **Способы защиты:** шифрование для хранения и передачи, обфускация (токенизация), маскировка реквизиты платежных инструментов (динамическая при отображении в интерфейсах и статическая при отправке в озеро данных), контроль доступа (RBAC/ABAC), аудит доступа, резервное копирование.
 4. **Финансовые данные компании**
    - Зарплаты
    - Платёжные реквизиты сотрудников для получения зарплаты
    - Бухгалтерские данные
    - Данные учета ТМЦ и закупок

    **Способы защиты:** шифрование для хранения и передачи, маскировка реквизиты платежных реквизитов (динамическая при отображении в интерфейсах и статическая при отправке в озеро данных), контроль доступа (RBAC), аудит доступа, резервное копирование.
5. **Перс. данные сотрудников (PHI)**
    - Ф.И.О
    - Паспортные данные
    - Адрес прописки
    - Семейное положение, Образование и т.д.
    - Контактная информация
    - Зарплата 
    - Налоговые данные
    **Способы защиты:** шифрование для хранения и передачи, обфускация (токенизация), маскировка (динамическая при отображении в интерфейсах и детерминированная при отправке в озеро данных), контроль доступа (RBAC/ABAC), аудит доступа, резервное копирование.
### Механизм тегирования данных
#### Теги по классам конфиденциальности:
    - **PII**: персональные данные пациентов
    - **PHI**: медицинские данные пациентов
    - **CLI**: клинические данные (анализы) пациентов
    - **FINP**: финансовые данные пациентов
    - **FINC**: финансовые данные компании
    - **INTERNAL**: данные сотрудников компании

Тегирование данных по классам конфиденциальности позволит автоматически соотносить данные с ролями пользователей, либо с доменами, предусматривающими ограничения доступа. Также позволяет корректно применять к ним методы защиты (маскирование, шифрование) и автоматизировать процессы обслуживания (отправка в долгосрочный архив или удаление).
#### Инструменты тегирования:
С учетом размера компании в текущем виде теги можно проставлять при введении новых данных в файлах, 1С и тд с помощью макросов, доработок 1С и скриптов.
При переходе на целевые автоматизированные системы и развития хранилища можно рассмотреть следующие системы для Data Lineage:
- **Apache Atlas** - open-source решение для хранилищ из экосистемы Hadoop.
- **Data Grail** - альтернативное платное решение, подходящее по бюджету и удобству интеграции.

### Cписок инструментов, способов и мер обеспечения конфиденциальности данных
- **Шифрование данных:** для хранения - AES-256, для передачи - TLS 1.3. Файлы с клиентскими данными должны шифроваться на уровне ОС (BitLocker)
- **Обфускация (токенизация):** необходимо исключить возможность прямого сопоставления медицинских, финансовых и иных данных пациента с его личностью (персональными данными), для чего можно реализовать механизм токенизации для пациента и сопоставление осуществлять с помощью уникального идентификатора
- **Контроль доступа (RBAC/ABAC):** доступ к данным должен определяться ролью сотрудника и специализированными атрибутами (врач должен иметь доступ только к своему журналу и к медицинским данным только своих пацентов); необходимо применение SSO (например, на базе Keycloack, возможно, с интеграцией с Active Directory) + RBAC/ABAC
- **Аудит доступа:** нужен полный лог действий по доступу к данным и их обработке + мониторинг "аномальности" действий с использованием SIEM систем (Splunk).
- **Автоматизация ввода и обработки данных:** необходима CRM для ведения пациентов, а также системы учета анализов, мед. историй и т.д. с автоматическим контролем целостности, классификацией и раздельным хранением данных
- **Резервное копирование:** необходимо обеспечить резервное копирование и хранение данных на нескольких серверах, для файлового сервера настроить версионирование
- **Физическая безопасность критических узлов:** необходимо разделить размещение AD, Exchange, систем 1С на отдельные физические серверы, т.к. взлом одной из систем может привести к утечке данных из всех остальных. Серверы должны быть размещены в защищенной комнате, доступ к которой имеется только у узкой группы авторизованных лиц
- **Актуализация версий ПО:** необходимо использовать последние версии ПО для минимизации эксплуатации известных уязвимостей: Microsoft Windows Server 2022 следует обновить до версии 2025
